# Чабани — вода + світло

Telegram-бот для Чабанів, який **автоматично бере підтверджені графіки ДТЕК** з відкритого репозиторію [XOTT69/dtek](https://github.com/XOTT69/dtek), використовує групу **1.2** для розрахунку води та групу **2.2** для світла вдома. Ручне пересилання графіків більше не потрібне.

## Логіка

- якщо за підтвердженим графіком у групи 1.2 є світло — вода є (фактичні аварії можуть відрізнятися);
- якщо група 1.2 відключена — діє резервний графік води;
- резервний графік можна оновити окремим пересланим повідомленням;
- бот рахує воду, світло 2.2 і спільні вікна вода + світло.

## 🤖 Автосинхронізація з ДТЕК

Уже наявний Cloudflare Worker `botvoda` працює за Cron `*/5 * * * *`.
На початку кожного запуску Worker читає **публічний JSON**, який
зберігає наш бот ДТЕК:

[Графіки та стан DTEK-бота](https://github.com/XOTT69/dtek/blob/main/state/publications.json)

Схема: **ДТЕК → XOTT69/dtek → GitHub JSON → botvoda/D1 → закріплене табло, Telegram-бот і персональні нагадування.**

- Читаємо **лише `scheduleSnapshots` з усіма 12 підтвердженими підгрупами**. Неповні дані, тижневі прогнози чи довільний текст Telegram не імпортуємо.
- В D1 зберігаємо **лише підгрупи 1.2 (вода) і 2.2 (світло)** для сьогоднішньої та завтрашньої дат. При новій даті автоматично додається відповідний графік.
- Якщо завтра ще **немає підтвердженого** графіка ДТЕК, його не вигадуємо й не перезаписуємо старі дані.
- Під час змін оновлюємо розрахунок води, світла й перетину, потім **редагуємо наявне закріплене табло**. Окремого зайвого поста в канал немає.
- Нові підтверджені графіки стають доступні в командах **«Сьогодні»** / **«Завтра»** та для персональних нагадувань.
- Повторні перевірки не переписують незмінний графік і не засмічують історію. Попередня версія зберігається для відкату.
- **Резервний графік водопостачання**, вручну встановлений фактичний стан і події про фактичну наявність електроенергії залишаються окремими.
- Тимчасова недоступність GitHub не зупиняє раніше збережені графіки та нагадування.

Після розгортання цього коду в Cloudflare Worker синхронізація ввімкнена
за замовчуванням і почнеться на найближчому Cron. Для ручної
перевірки власник бота може надіслати в особистий чат команду
**`/syncdtek`**: вона перевірить сьогодні й завтра, покаже що
оновлено, а якщо є зміни — оновить закріплений допис.

Вимкнення, якщо потрібне: Worker environment variable
`DTEK_AUTO_SYNC=off`. Інші токени, webhook-и й Cloudflare Worker
для репозиторію `XOTT69/dtek` не потрібні.

**Запуск у продакшені:** після зміни GitHub-коду перевірте, що
Cloudflare Workers Builds автоматично деплоїть `botvoda`, або разово
запустіть `npx wrangler deploy` зі свого налаштованого середовища.
Саме збереження коміту в GitHub **не гарантує** активації нової версії
Worker, якщо автодеплой не підключено.

## Можливості v0.4

- статус **зараз** і наступна зміна;
- графік сьогодні + завтра в одному закріпленому табло;
- попередній перегляд перед публікацією;
- показ різниці між старим і новим графіком;
- перевірка підозрілих або неповних даних;
- історія змін та відкат;
- окреме відображення можливих відключень;
- адмін-панель `/admin`;
- персональні нагадування 15 / 30 / 60 хв;
- мінімальна тривалість вікна для нагадувань;
- ранкове зведення;
- вечірнє зведення графіка на завтра;
- автоматичне редагування одного закріпленого повідомлення в каналі;
- фактичний стан світла з постів каналу `Світло зникло / Світло з'явилось`;
- ручний резервний режим світла через `/power`;
- статистика фактичних перемикань світла;
- тільки адміністратор може змінювати графік.

## Cloudflare

Worker: `botvoda`.

D1 binding: `DB`.

Потрібні Secrets:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_WEBHOOK_SECRET`
- `ADMIN_TELEGRAM_ID`

Для читання відкритого репозиторію ДТЕК **не потрібні додаткові секрети**.

Cron Trigger запускається кожні 5 хвилин.

Нові службові таблиці та колонки v0.4 створюються ботом автоматично, тому вручну виконувати SQL після оновлення не потрібно.

## Канал / група

Бот має бути адміністратором з правами публікувати, редагувати та закріплювати повідомлення.

Початкове підключення: `/setupgroup`

Перевірка: `/checkgroup`

Ручне оновлення табло: `/refreshgroup`

Після підключення бот зберігає message_id і надалі редагує саме це повідомлення.

## Фактичний стан світла

У підключеному каналі бот автоматично розпізнає нові пости з фразами `Світло зникло` та `Світло з'явилось`. Час береться з тексту повідомлення, якщо він є.

Пріоритет у блоці **ЗАРАЗ**:

1. ручний стан із `/power`;
2. остання фактична подія з каналу;
3. графік групи 2.2.

Нова фактична подія з каналу автоматично скасовує ручний override. Старі пости Telegram заднім числом не надсилає, тому після першого deploy поточний стан можна один раз виставити через `/power`.

## Приватна адмін-аналітика

Команда `/analytics` і кнопка **📊 Аналітика** доступні тільки користувачу, чий Telegram ID збігається з `ADMIN_TELEGRAM_ID`.

Аналітика показує:

- загальну кількість користувачів;
- нових та активних за сьогодні / 7 / 30 днів;
- скільки людей прийшло через `?start=chabany` із кнопки каналу;
- активні типи нагадувань і вибір 15 / 30 / 60 хв;
- кількість фактично відправлених нагадувань;
- останніх користувачів з ім'ям, username, джерелом та останньою активністю;
- денну активність за останні 7 днів.

Старі користувачі автоматично переносяться в аналітику з Telegram ID. Ім'я та username доповнюються після їх наступної взаємодії з ботом.
